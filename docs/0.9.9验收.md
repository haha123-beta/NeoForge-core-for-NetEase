## 实际修复

- Java Unicode 预处理：按 JLS 21 的反斜杠资格规则单次展开，处理注释、转义关键字和代理对；诊断物理行号映射回原件。非法转义仍拒绝。单独代理项和 Unicode 与 Mixin 编辑的字节位置组合保持明确阻断。
- 字段与方法分离：复用已有声明者存储命名，让源代码实例字段与同名 getter 共存；字段读写与访问器不再覆盖彼此。私有访问、静态字段冲突和其他未审查继承布局仍拒绝。
- 类型接线：已审查继承关系同时用于重载选择与泛型边界证明，修复 ModConfigSpec 到 IConfigSpec 的断路；已知嵌套 API 的完整限定名复用实际导出。
- 泛型约束：同一泛型声明的赋值保持不变性；有受审查合同的注册工厂按目标类型求解 Supplier 结果与 Item/Block 上界。菱形构造保留目标上下文。没有擦掉未知泛型父类，也没有实现完整泛型系统。
- 现有 API：接通 Component.literal/empty/getString、ModContainer.registerConfig 和配置类型常量。文本返回值规范为 Java String；接口静态方法只允许类型限定调用。Component.translatable/nullToEmpty 等尚未验证等价的重载继续拒绝。

## 自动候选与回归

保留原 A/B/C 分工，新增受信任的 reviewed_foundations099_v1 批次。它只处理受审查且 SHA256 精确匹配的补丁集合：历史真实阻断证据 → 候选与差异 → Java/真实 Python 2/Python 3 对照 → 全量回归 → 源码完整性复核 → 应用。候选不能自行选择目标路径、补丁内容或验证命令。未知版本、候选篡改、路径越界、验证失败或验证期间源码变化均拒绝应用。

```powershell
python run_neocore.py mining propose PATH_TO_RUN --recipe reviewed_foundations099_v1 --output candidate
python run_neocore.py mining validate-patch candidate --apply
```

本版本已安装这些规则时，提出候选返回 ALREADY_INSTALLED；不要在未知编译器版本上强行套用。完整历史回归需要固定参考 JAR、JDK 和 Python 2，缺失时拒绝通过。
